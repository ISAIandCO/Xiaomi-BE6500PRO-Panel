RD08 1.1.123 SECURITY CONTRACTS — 2026-11-08
Static controller bytecode + five safe live reads. No setters or scans run.
All routes below are relative to /cgi-bin/luci/;stok=.../api/.
Use ordinary form encoding. Values containing arrays must be JSON strings,
not nested form array fields. Validate all MACs as individual colon-separated
addresses and select known devices; firmware checks are weaker than panel's.
No numeric/list size limit is enforced explicitly in these controller inputs;
panel must use its own bounded limits. 0/1 fields should be sent as strings.

CONFIG SCANNER — luci/controller/config_scan/index.lua
The ROUTE namespace is config_scanner, not config_scan.
GET overview -> keys {check:{enable_scan:0|1},meta:{last_score},code:0}
  Live enable_scan1: rom_auto_updating,anti_squatter,UPnP,newest_rom,
  wifi_passwd_secure,port_mapping,DMZ,wifi_encryption; last_score73.
  publicData's broad password regexp currently turns wifi_passwd_secure into
  hasPassword:true. Normalize this KNOWN nonsecret check to wifiKeyStrength
  before redaction, both standalone and nested sec_center.config_scanner.
POST config {<existing check key>:'0'|'1', ...} -> {code:0}
  1 means include scan (ignored=0), 0 means ignore. Unspecified checks remain.
  Only expose keys whose overview value contains enable_scan; exclude meta.
  config is NOT a getter: even zero fields acquires a lock/commits UCI.
POST start {} -> {code:0,meta:{work_id:STRING}} or {code:-1,msg:'resource busy'}
  Generates unique random work_id strings1..1000, prepares temp status and
  forks Lua scanner. No network reset is present in controller.
GET get_status {work_id:STRING} -> {code:0,<check>:{status,secure,enable_scan},
  meta:{status,score,running:CHECK_NAME?}} or {code:-1}
  status0/1/2 represent prepared/running/done in config_scan.common.
  secure is a score (typically0/1), not necessarily boolean; meta.score is
  floor(100*score). Work IDs can expire; do not poll endlessly after -1.
POST stop {work_id:STRING} -> final status object
  Stops the spawned process, then produces status. Controller accepts any
  known temporary work_id: panel should bind stop/status to its started job.
  Read polling refreshes temporary job timestamp; jobs are bounded/cleaned.
  No live scanner start/config/stop was performed in this research.

  Session is mandatory. It is obtained by the stock blocked-site page via

  Success requires verifySession.code==0. Failure MAY RETURN CODE0 WITHOUT

  Do not invent a generic unverified whitelist-adder.

  Actual live on1, risk_cnt2,sys_cnt29,nic_cnt454.
GET mi_log/get_logs {type:'risk'|'sys'|'nic',tsclient:UNIX_SECONDS,
  duration:DAYS,offset:INTEGER,limit:INTEGER}
  tsclient and duration required (otherwise1523). type defaults sys,
  offset defaults0, limit defaults10. Source has no upper bound; panel should
  cap page size, offset/days. Query uses timestamp<=tsclient and recent days.
  -> {code:0,msg,total,count,info:[{date:'YYYY-MM-DD',data:[
    {time:'HH:MM',ts,id,type,msg,ext,mac,dev},...
  ]},...]}. Fields vary per event. Times/dates use router timezone.
POST mi_log/del_logs {type:'ids'|'duration',value:STRING,
  filter:'risk'|'sys'|'nic'?}
  CORRECTED VM map proves type=='duration' selects days; any other type
  selects IDs. IDs: type='ids',value=JSON array of known decimal IDs.
  get_ids_from_str strips brackets and extracts decimal IDs; filter ignored
  in the IDs branch. Days: type='duration',value=integer DAYS, optional filter
  narrows sec_<filter> prefix. Without filter all tags in the day range may
  be removed. del_by_days selects TIMESTAMP>=DATE(now,-DAYS,localtime), so
  this deletes RECENT days, not records older than N days.
  Deletion is irreversible: require user's explicit selected-record review.

CENTRAL / BLUETOOTH MESH
The public MIoT spec for xiaomi.router.rd08 has services1,2,5,7 only, no
Bluetooth gateway property. Cached public response: security-rd08-miot-spec.json.
URL: https://miot-spec.org/miot-spec-v2/instance?type=urn:miot-spec-v2:device:router:0000A036:xiaomi-rd08:1
Native firmware miio_bt RPC table includes miIO.ble_gateway_state at414d8c,
miIO.ble_gateway_enable at415a3c, miIO.bt_gateway_version at414b6c.
Exact refs: security-bt-rpc-refs.json. Enable handler explicitly gets request
params object and integer state field; no write has been sent.
State getter returns result:{state:INTEGER}. Native setter payload:
  {id:1,method:'miIO.ble_gateway_enable',params:{state:0|1}}
Do not invoke setter through an unverified/failed transport.
Two exact fixed live getters were tried via request_miio POST payload JSON:
  {id:1,method:'miIO.ble_gateway_state',params:{}}
  {id:1,method:'miIO.bt_gateway_version',params:{}}
BOTH returned {code:-1,msg:''}; security-bt-live.json records sanitized
requests and answers. There is no usable BT state through this legacy path.
Static dispatch: thrifttunnel case6 jump at0xbc04 -> GOT0x41bb8 ->0x1f694,
constructs a MiioThrift client to localhost:9098 with20-second timeouts.
The supplied rootfs has no usr/sbin/miiothrift, usr/bin/miiothrift or
etc/init.d/miiothrift. This supports an unavailable legacy backend, rather
than proof that the native BT handler lacks the function. A cloud/MIIO or
central-container connection with proper device/account authorization would
be a separate transport; no account keys/token were obtained here.
Do not display code-1 as gateway-off. Return unavailable and explain transport.

not ordinary443 Host forwarding. It rewrites to /cgi-bin/luci/url_fw.
