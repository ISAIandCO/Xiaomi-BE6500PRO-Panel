1. Local web token endpoints are NOT MIIO device tokens
   xqsystem/token -> getToken returns dispatcher.context.urltoken.stok,
   the existing LuCI web session. It also returns device identifiers/name.
   Therefore it cannot be used as the16-byte MIIO UDP encryption key.
   This was established from source; no token endpoint call was needed.

   xqsystem/oneclick_get_remote_token ->
   XQExtendWifi.oneClickGetRemoteTokenForLua(username,password,nonce).
   The helper reads peer_ip from /tmp/replace_router, cleans migration token
   records, GETs the PEER router's /cgi-bin/luci/api/xqsystem/token, and writes
   returned web-session token to the migration state file. This is a router
   replacement/migration helper with writes, not a MIIO-token getter.
   It was NOT called. xqsystem/renew_token similarly creates web sessions.

   miio_ot.ot.token, initializes it from ntoken if absent, and sends it through
   the internal MIIO helper channel. update_dtoken changes/persists it.
   No runtime config/key file was read, displayed or copied.

   security-miio-constants.py decoded215 Fate/Z modules with zero errors and
   searched for miio_ot,miio_token,miot_key,centralCtl,ble_gateway,miotcentral,

   they read bound/ver/device-ID information, not ot.token. Plain Lua text
   search found no additional matching bridge. Evidence: security-miio-constants.json.
   This is bounded evidence about supplied Lua modules, not a mathematical
   claim that every possible binary/admin interface has been excluded.

   This is a getter using the router's existing Xiaomi-bound service identity.

   setUIState/update/getAPILevel locally and forwards other methods to the
   Central container. Access to these Unix sockets requires a process on the
   router; no LuCI route to them was found. No socket command was executed.

Conclusion under CURRENT available authorization and credentials
There is no verified working BT/Central setter transport through this local
panel's existing web-admin session. Native RPC payloads are known, but a
failed getter, missing MIIO token and absence of a client certificate prevent
honest control. Continuing needs a valid token for this exact device from an
authorized source, new Xiaomi account OAuth/certificate setup with support for
this gateway, or separately authorized on-router shell access. Do not add a
fake functioning switch or bypass package/token/certificate authentication.
