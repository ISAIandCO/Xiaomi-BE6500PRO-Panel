XIAOMI BE6500 PRO RD08 — ПАНЕЛЬ1.2.0
09.11.2026. Реальное устройство: RD08, CN, прошивка1.1.123.

Результат
20 разделов; сохранены существующие Wi-Fi/WAN/LAN/NAT/VPN/DDNS/QoS,
добавлено управление расписаниями, IoT firewall, категориями фильтра,
журналами, сканером, приложениями родительского контроля, Mesh-привязками,
Dual WAN, системными операциями и установкой подписанного плагина.
Матрица FUNCTION-MATRIX.csv (70 строк) сравнивает веб/Home/API и итоговую панель.
Список656 зарегистрированных API в research/api-inventory.csv — инвентарь
образа, включающий устаревшие и условные обработчики других моделей.
Количество маршрутов не является числом работающих функций RD08.

Что изменено
core.mjs — существующие настройки и фиксированные сцены планировщика.
network-plans.mjs — dBm/RSSI, Mesh/клиентские привязки, WAN lifecycle,
Dual WAN/веса, guest QoS и приложения с квотами0–1440 минут. Нулевая квота
означает нулевое разрешённое время; выключение категории сохраняет правила.
security-plans.mjs — IoT-доверие, URL-политики, scanner и удаление видимых
ID журналов. Глобальное удаление «по возрасту» не имитируется: штатная
операция days удаляет последние N дней, а не записи старше этого срока.
system-plans.mjs/timezones.json — система,113 точных index/TZ пар прошивки,
подтверждаемые reboot/reset/upgrade/restore и одноразовые этапы загрузки.
utility-plans.mjs — WPS PBC/статус/отмена и явный штатный speedtest.
plugin-package.mjs/system-file.mjs — локальный разбор с ограничениями
размеров, путей, ссылок, CRC и подписей без извлечения/исполнения файлов.
miio-local.mjs — ограниченный транспорт только3 известных BT RPC.
server.mjs — прежняя локальная авторизация/CSRF/TLS pin, чтение по allowlist,
предпросмотр/одноразовое применение, файлы в RAM, привязка заданий и staged
файлов к сеансу. Другой сеанс панели не может применить заменённый файл.
public/app.js,system-ui.js,utilities-ui.js — формы и раскрываемые разделы.

Плагины: что установлено фактически
Ничего не устанавливалось. Custom Hosts в installed_plug — встроенная
запись /usr/share/pluginmanager/hosts.json; status0 не доказывает запуск.
Подтверждён путь upload_plug → mkxqplugin → native manager/datacenter.
Веб-пакет требует HDR1/RSA-SHA1 с plugin_public.pem, модель RD08 и ROM,
вложенный MIPK требует правильные CRC/signType/manifest/SDK/ZIP и подпись.
Доверие привязано к собственным ключам Xiaomi, включая MIWIFI RSA2048.
История TLS-сертификатов eMudhra не предоставляет эти закрытые ключи.
Старый официальный Linux x86_64 packager2014 выдаёт rawMIPK/signType0,
а исследованный менеджер требует1; этого инструмента и старого сертификата
недостаточно для текущего веб-пути. Современная повторная подпись/доставка
Xiaomi не подтверждена. Исходник рабочего по смыслу статус-плагина подготовлен
в examples/rd08-status; инструкция объясняет AppID, SDK, Linux-права,
подписание и установку. Он не выдаётся за установленное расширение.
Положительный тест vendor-signed plugin отсутствует: подходящего образца нет.
Mi-Stat_Max — браузерный userscript, ShellCrash — установка с системными
привилегиями. Их наличие не доказывает совместимость штатной .mpk-загрузки.

Проверка на реальном RD08
Все20 групп чтения и37 предпросмотров прошли без apply. Сеансы исследований закрыты.
Резервная копия7717 байт получена только в RAM: gzip/TAR/описание разделов
успешно проверены; содержимое и пароли не сохранялись в исследовательский лог.
Отдельно проверена штатная TLS-страница URL-фильтра на8900 с тем же TLS pin.
Она корректно отображает домен, но возвращает session0. Добавление исключения
сейчас не работает из-за отсутствия результата ubus-службы DPI; настройки
UCI/чтение политик не подтверждают здоровье этой службы. Панель не обходит
проверку и не сообщает ложный успех. Нормальный путь при исправном backend:
разрешение со страницы → один add_whitelist → проверка появления в списке.
verifySession отдельно не вызывается: успешная проверка расходует разрешение.
Текущий список заданий пуст; предпросмотр нового задания прошёл. WPS закрыт, разрешение выключено, wpa3_only=1. Геттер последнего speedtest вернул1588 (результат отсутствует/ошибка); сам тест не запускался.
Сырые результаты live-smoke не включены в публичный репозиторий.

Локальные и браузерные проверки
80 автотестов проходят: валидация параметров/единиц/самоблокировки, сохранение секретов,
сеансы/CSRF/one-use, scanner/log IDs, замена staged-файла между сеансами,
пароль SHA1+SHA256/AES128CBC, упаковки/бомбы/подписи и протокол miIO.
Официальный образ1.1.123 (87706132 байта) положительно проверен офлайн:
HDR1/CRC/RSA-SHA256/public.pem/RD08/hardwareID81/версия/4 секции.
SHA256 c4d3259dae532ba1e50d55e914c8759f06e1568f42d2e708d0a69337bc5c9093.
Алгоритм подписи firmware отличается от plugin: использовать один для обоих
было бы ошибкой. Образ содержит uboot.bin; никакой передачи/прошивки не было.
20 страниц макета открыты без JS warnings/errors; проверены предпросмотры
OTA/перезапуска и отмена, scanner, IoT, квота приложений и неподходящий пакет.
Файловые эндпойнты проверены тестами HTTP; автоматический выбор файла в IAB
не подтвердился. Нативный input остаётся стандартным диалогом браузера.

Операции с реальным применением не проверялись
Новые settings/setters, WPA/провайдерские режимы, VPN/DDNS-аккаунты,
second Mesh, WPS pairing, нагрузочный speedtest, plugin upload/install,
пароль, reset/reboot, firmware flash/restore. Они не выполнялись специально,
чтобы сохранить действующую сеть в рамках разрешённой проверки.
Предпросмотр подтверждает построение запроса; он не доказывает изменение
железа. Ошибки после отправки могут иметь частичный/неизвестный результат.

Технические границы
• BT: доказан UDP54321 → miio_client → TCP54323 → miio_bt. В панели есть
  ввод собственного токена, проверка state/version и readback переключения.
  Веб-stok не является miIO-токеном. Обычный matool getter не выдал selftoken;
  BT legacy bridge не работает. Нет токена — нет реального теста. Установка
  miio_bt зависит от bound и обновляемого бинарника; RPC может быть запрещён.
  Central software pack0.11.5 — отдельный Docker-компонент, не версия BT SDK.
• Hosts SDK возвращает1500: MAC ACL sdkfilter проверяется до обычной сессии.
  Нет доказанного администраторами пути выдачи разрешения; подмена роли не
  применяется. Lifecycle собственных native plugin без совместимого пакета
  не проверен; произвольный datacenter JSON наружу не выставлен.
• NetEase UU/Youbangbang, cloud-привязка/удалённое управление, управление
  Central требуют других контрактов/авторизации. Полного RD08 Home-плагина
  в предоставленном APK нет: найден общий routerinitial. Обычный веб-пароль
  не заменяет Xiaomi OAuth, user certificate или developer signing.
• Удаление общего офлайн-клиента заявлено в Home changelog, но точного
  локального API нет в изученных LuCI/trafficd/MIoT. Удаление IoT-защиты и
  блокировка клиента имеют другое действие и не подменяют эту функцию.
• Static routes, новые VPN-движки/ipk, контейнеры и температура требуют
  подтверждённого API либо другого доступа. Root/SSH/прошивка не выполнялись.
Панель не заявляет универсального паритета со всеми облачными функциями.
