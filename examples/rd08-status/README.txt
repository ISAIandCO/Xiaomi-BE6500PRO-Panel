RD08 STATUS EXAMPLE — ИСХОДНИК ПЛАГИНА, НЕ УСТАНОВЛЕННЫЙ ПАКЕТ

Назначение
Пример раз в минуту читает /proc/uptime и записывает status.json только в
собственном каталоге. Он не открывает порт, не обращается в Интернет, не меняет
DNS, маршруты, firewall или Wi-Fi. Менеджер управляет остановкой процесса;
POSIX-скрипт обрабатывает TERM/INT/HUP и удаляет только свой временный файл.

Важно: start_script — НЕ shell-скрипт. Это небольшой DSL менеджера Xiaomi.
Официальный SDK требует хотя бы одну команду RUN для программы плагина.
Здесь RUN запускает отдельный POSIX-скрипт status_worker.sh. Права исполнения
status_worker.sh нужно сохранить при упаковке ZIP на Linux (chmod 755).
На роутере пример не запускался. Его установка из этой папки невозможна:
AppID, страницы управления и Xiaomi-выданного сертификата здесь нет.

Подготовка
1. Нужны зарегистрированное приложение роутера Xiaomi, назначенный AppID,
   данные разработчика и URL страницы управления из его настроек.
2. Заполнить REPLACE_* в xiaomi.project своими данными. Private key и
   сертификат хранить отдельно от проекта, не добавлять в архив/репозиторий.
3. Требуется сертификат разработчика, выданный Xiaomi по CSR. Самоподписанный
   сертификат не заменяет доверие прошивки. Работоспособность выдачи таких
   сертификатов сейчас ещё не установлена.
4. supported_rom=miwifi_rom_2 и sdk_level=5 взяты из текущего RD08 1.1.123.
   Эти значения отличаются от примеров старых R1D/R1CM. ARM/MIPS-библиотеки
   старого SDK не подходят автоматически к AArch64/musl RD08. Данный пример
   использует только /bin/sh, awk, mv, sleep из базовой системы.

Официальный упаковщик
Документация SDK5: https://dev.mi.com/docs/routerplugin/user_guide/
Архив: https://bigota.miwifi.com/xiaoqiang/sdk/tools/sdk_package.zip
Скачан 08.11.2026, 3 883 169 байт, SHA256:
4f52b407981bd3b03b56445548e4ecc51f1229299921d5382a54fabebdd0c10a
Архив содержит Linux x86_64 plugin_packager_x64, x86-вариант, xiaomi.project,
заголовки и старые библиотеки. Дата файлов 2014-06-27. Упаковщик не запускался.
Только исследован формат ELF и имена функций DigitalSign/PluginPackager.

Описанный Xiaomi порядок на отдельной Linux-системе после проверки инструмента:
  cd /path/to/plugin-sdk-example
  chmod 755 payload/status_worker.sh
  /path/to/vendor/sdk_package/plugin_packager_x64
Он читает xiaomi.project в текущем каталоге. В документации результат — app.mpk.
Важное установленное ограничение: его signPackageFun передаёт SignType=0
(x86_64 адрес 0x403536), а DigitalSign записывает это в MIPK offset0x0c.
Нативный pluginmanager RD08 в 0x5770..577c требует SignType=1. Поэтому
результат именно этого старого упаковщика несовместим с данным локальным
путём установки даже при наличии старого сертификата разработчика. Не
выдавайте app.mpk этого инструмента за готовый к установке RD08-пакет.
Документированный исторический порядок оставлен для воспроизводимости;
нужен современный совместимый путь подписи/распространения Xiaomi.
Не запускать упаковщик на
самом роутере: это программа x86_64 для рабочей станции.

Форматы и установка
Расширение .mpk неоднозначно. Старый SDK подписывает контейнер MIPK, а
штатный веб-upload_plug текущей прошивки сначала вызывает mkxqplugin -X -F,
который проверяет внешнюю оболочку HDR1, ROM/model metadata и подпись Xiaomi.
Затем pluginmanager проверяет вложенный MIPK и manifest. Переименование ZIP,
самоподпись или простое добавление заголовка не дают доверенного пакета.
Если у разработчика есть только старый MIPK, необходимо выяснить официальный
поддерживаемый путь доставки/обёртывания у Xiaomi; нельзя называть его готовым
пакетом для текущей веб-загрузки. Историческая установка через MiWiFi App
из официального руководства не испытана на этом RD08/Xiaomi Home.

Подтверждённый кодом веб-путь для готового совместимого vendor-signed пакета:
  POST /cgi-bin/luci/;stok=SESSION/api/xqsystem/upload_plug
  multipart/form-data, поле image
Вариант /uploadfile/cgi-bin/... передаёт тело через файл nginx. Штатный Lua
обработчик проверяет свободное место; пределы nginx зависят от location/UCI.
Сначала нужно выполнить локальную проверку формата/модели/подписей/manifest,
показать пользователю точный пакет и только потом отправлять файл.

Нативные операции pluginmanager (не доказано, что все напрямую доступны
через datacenter на текущем устройстве):
  601 — список; готовый LuCI getter xqsystem/installed_plug подтверждён.
  602 — локальная установка: pluginPath (LuCI передаёт /tmp/unified_plug.mpk).
  604 — прогресс: ids (строка идентификаторов, формат разделения см. контракт).
  605 — удаление: pluginID.
  606 — статус: pluginID, status (5 — запуск, 6/7 — остановка по веткам кода).
Веб-туннель /service/datacenter/request принимает JSON в поле payload;
маршрутизацию каждого lifecycle API нужно подтвердить чтением и тестами.
Не направлять произвольные JSON-команды пользователя и не выполнять startup
API600: он запускает инициализацию всего менеджера.

Что фактически готово
Исходник и схема конфигурации для подписания; точный анализ проверок штатной
прошивки. Доверенная подпись, окончательный installable package и установка
на RD08 пока не подтверждены. Это нельзя скрывать под названием «установлено».
